# YUNY Organicity & Continuous Acceptance Matrix — v4.5 RC

## Purpose
The system must behave like an integrated production team, not a pile of rules.

## Organicity tests

### O1 — Intent to field trace
Given a user premise, every important intent item must land in:
- lyric mode
- vocal fit
- CREATE bone
- COVER transform/refine
- cue plan
- EXCLUDE/sliders
If an intent item is only discussed but lands nowhere, fail.

### O2 — Mode diversity
A Korean lyric request must not always route to the same writer-room shape.
Required modes:
- conversational/narrative
- poetic/symbolic
- surreal/artful
- chant/anthem
- vocable/phonetic
- bilingual
- theatrical/character
- minimal/fragment

Each mode changes what counts as a failure. Abstraction, fragmentation, slogan, or nonsense syllable can be valid when mode-locked.

### O3 — CREATE/COVER triangle
Before 8-field output:
- CREATE = bone only
- COVER = preserve/substitute/quality/final
- Audio Influence matches intent
If COVER reads like a fresh song, fail.

### O4 — Cue call-response
Cues must answer lyric or arrangement events:
- confession → drop/silence only if next line is strongest
- hook entry → breath or sudden drop
- final variation → harmony/held/double
- bridge rupture → band drop
Cue spam without line-event cause fails.

### O5 — Cover quality stack
Serious COVER must include:
- vocal corridor
- low-end separation
- low-mid mud control
- high-mid/air smoothness
- stereo/depth
- dynamics/finish

### O6 — Diagnostic stop ladder
Repeated complaint cannot trigger endless synonym patching.
One complaint = targeted fix.
Two = rebuild one phase upstream.
Three = two concrete direction choices.

### O7 — Source assimilation
New data enters as gates, patterns, and tests. It cannot override intent lock or copy text.

### O8 — Final package discipline
Final package must contain exactly:
1_PROJECT_INSTRUCTIONS/
2_KNOWLEDGE_FILES/
3_GITHUB_UPLOAD_STRUCTURE/

No live-update claim until applied.

## RC-to-final graduation
A package can be called final only when:
- 20 knowledge files exist
- instructions are measured and under limit
- data-intake path exists
- acceptance tests cover lyric modes + CREATE/COVER + cue + cover quality
- audit report declares no known blocking contradiction
- patch/full zips are generated
