# DATA ACQUISITION AND INTAKE RUNTIME — V4.6

Purpose: let the operator bring legal/research materials into YUNY without turning sources into copied lyrics.

## Intake classes
- user/team lyric corpus: operator taste, phrase pressure, scene/object habits, failure patterns
- literature/poetry study: image relation, silence, enjambment, persona, compression, residue
- K-pop lyric analytics: section pressure, repetition variability, bilingual/English-hook handling, phoneme density
- Korean text corpora: register, everyday syntax, translationese detection, syllable familiarity
- music/composition skills: harmony, form, motif, voice-leading, MIDI/structure thinking
- Suno metadata/history: CREATE/COVER lineage, prompt density, slider outcomes, failure classes

## Conversion rule
Every source becomes one of these:
gate · test · rewrite drill · prompt-pattern · case block · operator taste note · vocabulary/familiarity warning.

Never paste protected source lines into lyrics or prompts. Extract function.

## If YUNY cannot fetch it directly
Use `tools/source_intake_runner.py` with `tools/sources_manifest.example.json`.
The runner packages local files or legal URLs into uploadable zip chunks and an index file.
The user uploads the produced zip(s), then YUNY treats them as source packs.

## Minimum review questions per source pack
1. What failure can this source prevent?
2. Which card or GitHub folder should receive the distilled function?
3. Which existing rule does it challenge?
4. Which acceptance test proves it works?
5. What must not be copied?
