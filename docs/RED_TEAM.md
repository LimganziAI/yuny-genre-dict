# RED TEAM — 이 시스템이 다시 망가질 10가지와 방지책

1. **게이트 연극** — 평가가 도장이 됨. 방지: 행 인용 의무 + PASS여도 최약 2행 지목 쿼터 + 스모크 AT 불시 적용.
2. **hard gate 인플레** — 모든 선호가 게이트로 승격돼 결과물이 딱딱해짐. 방지: 게이트 5개 동결, 신규 1 = 기존 1 은퇴. soft는 굽힐 수 있는 채로 둔다.
3. **INTENT LOCK 오작성** — 의도를 오독한 채 동결. 방지: STOP-0 에코 1회(가장 싼 지점의 보험) + "다르면 한 줄로 고쳐줘".
4. **plain draft 산문 과잉** — 압축 불가능한 만연체. 방지: 스파인 5-7 상한 + "말할 수 있는 문장" 기준 + 압축 예산 사전 인지.
5. **평가 패스의 월권** — 판정하다 재작성 시작. 방지: 판정 포맷 고정(PASS/FAIL+행 인용), 재작성 권한 없음 — 재작성은 생성 패스의 일.
6. **압박에 게이트 생략** — "그냥 빨리 줘". 방지: "빨리"=SKETCH 모드(게이트 압축 실행)지 게이트 0이 아님.
7. **큐 쿼터 게이밍** — device를 섹션 끝에 몰아넣음. 방지: 위치 감사(라인 사이 실배치) — AT-N3 포함.
8. **렌더 분산↔프롬프트 결함 혼동** — 방지: 삼분 triage 선행 + render_count 기록. 단 가사 불만에 랜덤 알리바이 금지(가사는 그대로 실현).
9. **originality ledger 역작용** — 낯섦 강박으로 좋은 수법까지 회피. 방지: ledger는 표면(사물·엔딩·어미)만 차단, 품질 수법(열린 모음 훅 등)은 면제 목록.
10. **규칙 더미 회귀** — 이 패키지조차 텍스트를 늘린다. 방지: 모든 애든덤은 무엇을 은퇴/압축시키는지 명기 + 분기별 카드 사이즈 감사 + 승격 사다리 엄수(케이스→패턴→카드→Instructions). **결과물이 딱딱해지는 신호 = soft 룰이 hard처럼 행동하는 것** — 발견 즉시 L2로 강등.
