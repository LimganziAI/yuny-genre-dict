## 0. 한 장 요약 — 3분할 구조

지금 클로드에선 시스템지침 + .md 29개 + 깃허브 장르사전이 한 프로젝트 안에 다 들어가 있어.
챗지피티는 구조가 달라서 **세 군데로 쪼개야** 한다.

```
┌─────────────────────────────────────────────────────────────┐
│ ① Custom GPT  [Instructions 필드]   ← 8,000자 하드 한도         │
│    = 헌법 + 라우팅 (네가 압축 중인 8000자 master)               │
│    = 00_SYSTEM_INSTRUCTION 의 압축본(v5)                        │
├─────────────────────────────────────────────────────────────┤
│ ② Custom GPT  [Knowledge 파일]      ← 약 20개 한도              │
│    = 매 곡 꺼내 쓰는 craft 파일 (화성/가사/보컬/사운드/편곡…)    │
│    = 이 패키지의  B_ 폴더  (정확히 20개로 맞춰둠)               │
├─────────────────────────────────────────────────────────────┤
│ ③ GitHub  [raw URL fetch]                                     │
│    = 장르사전 277개 (이미 있음) + 개인경험/케이스 + 20개 초과분 │
│    = 이 패키지의  C_ / D_ / E_ 폴더                            │
└─────────────────────────────────────────────────────────────┘
```

**왜 이렇게 나누나 (제약 두 개):**
- **Instructions 8,000자**: Custom GPT 지침 입력칸은 8,000자에서 저장이 막힌다. → 그래서 네가 master를 8000자로 압축 중인 거고, 그게 정확히 이 칸에 들어간다.
- **Knowledge 약 20파일**: GPT 빌더 Knowledge는 파일 20개까지(파일당 최대 512MB·200만 토큰). 근데 우리 craft .md만 27개라 **그냥 다 못 올린다.** → 매 곡 쓰는 20개만 Knowledge, 나머지(가끔 참조 + 개인경험 + 사전)는 GitHub로 뺀다.

## 2. 셋업 순서 (Custom GPT 기준)

### Step 1 — Custom GPT 생성 + 기능 켜기
ChatGPT → 좌측 **GPTs → + Create → Configure** 탭.
**Capabilities 반드시 체크:**
- ☑ **Web Search / Browsing** — GitHub raw URL fetch에 필수 (= 클로드의 curl 대체)
- ☑ **Code Interpreter & Data Analysis** — 글자수 실측에 필수 (= `wc -m` 대체, Python `len()`)
- ☐ Canvas(선택) — 가사/긴 산출물 편집 편하면

### Step 2 — Instructions 칸 = 8000자 압축본(v5)
`A_` 폴더의 풀버전이 아니라, **압축 완료된 8000자 master**를 붙인다.
(압축 v5가 아직이면 이게 이관의 마지막 블로커 — §4 참고. 임시로 풀버전 앞부분만 넣고 시작해도 되지만 8000자 넘으면 저장 안 됨.)
압축본 안에 **GitHub BASE URL과 라우팅 트리거**가 들어가야 함(Step 5).

### Step 3 — Knowledge 업로드
Configure → **Knowledge → Upload files** → `B_` 폴더의 **20개 전부** 업로드. 끝.

### Step 4 — GitHub repo 구성
- **기존 유지:** `LimganziAI/yuny-genre-dict` (장르사전 277 + 23a) — 손 안 댐.
- **새 repo 1개 생성** (예: `LimganziAI/yuny-system`), 폴더 구조:
  ```
  yuny-system/
  ├── vault/
  │   ├── 99_OPERATOR_VAULT.md      ← D_ 폴더
  │   └── 99z_SESSION_LOG.md         ← D_ 폴더
  ├── reference/
  │   ├── 00_ROUTER.md               ┐
  │   ├── 01_OPERATING_RULES.md      │
  │   ├── 05_GENRE_LIBRARY.md        │ E_ 폴더 통째로
  │   ├── 12_PROMPT_TEMPLATES.md     │
  │   ├── 13_REFERENCE_ANALYSIS.md   │
  │   ├── 18_RESPONSE_TEMPLATES.md   │
  │   ├── 19_DIAGNOSTIC_CHECKLISTS.md│
  │   └── 22_KPOP_ARTIST_DEEP_DIVES.md┘
  └── CHANGELOG.txt
  ```
  > Private repo면 ChatGPT가 못 읽는다. **Public**이거나, Private이면 Step 5의 Actions(토큰 인증) 방식으로 가야 함.

### Step 5 — 압축본에 GitHub 라우팅 심기
8000자 master 안에 fetch 규약을 박아둔다. 예:
```
GitHub BASE:
  사전 = https://raw.githubusercontent.com/LimganziAI/yuny-genre-dict/main/
  시스템 = https://raw.githubusercontent.com/LimganziAI/yuny-system/main/
규약: 장르본문 필요 → 사전 BASE+slug 경로 browse.
      케이스/경험 필요 → 시스템 BASE+vault/99_OPERATOR_VAULT.md browse.
      진단/템플릿 등 가끔자료 → 시스템 BASE+reference/<파일> browse.
```
*(브랜치가 master면 main을 master로. 레포 이름은 네가 정한 걸로.)*

### Step 6 — 작동 테스트 3개
1. **fetch:** "신스웨이브 장르 사전 열어봐" → GitHub raw 열고 내용 인용하나?
2. **글자수:** "이 Style Box 글자수 재줘" → Code Interpreter로 `len()` 돌려 숫자 내나?
3. **자료-우선:** "한국어 가사 한 곡 써줘" → 07/14/25/17 Knowledge부터 참조하고 시작하나?

## 3. 클로드 → 챗지피티, 바뀌는 것 (압축본 손볼 포인트)

지침을 옮길 때 **메커니즘 단어**를 챗지피티 것으로 바꿔야 함. 의미는 같고 도구만 다름.

| 클로드(현재) | 챗지피티(이관 후) | 지침에서 고칠 표현 |
|---|---|---|
| `curl raw.githubusercontent.com` | **Web Browsing** 으로 raw URL 열기 | "curl로 fetch" → "browse the raw GitHub URL" |
| `wc -m`, `printf…\|wc -m` | **Code Interpreter** Python `len(str)` | "wc -m로 실측" → "Code Interpreter로 len() 실측" |
| `/mnt/project/<파일>` 경로 | Knowledge 파일명 또는 GitHub raw URL | 경로 참조 → "Knowledge의 07 파일" / "GitHub reference/" |
| bash 도구 일반 | 챗지피티엔 일반 bash 없음 (Code Interpreter 샌드박스만) | bash 전제 문구 제거 |
| 한국어 멀티바이트 `wc -m` 주의 | Python `len()`이 코드포인트 기준 = 더 정확 | 오히려 단순해짐 |

**나머지 로직(제0원칙·7-블록·자료-우선·가사 LAW·§18 Cascade 등)은 그대로 유효.** 도구 호출 어휘만 교체하면 됨.

> 주의: 챗지피티(GPT-5.x)는 클로드와 지침 해석 결이 약간 달라. 압축본 옮긴 직후
> **테스트 곡 2~3개 돌려서** 자료-우선이 실제 발동하는지, 7-블록 형식 지키는지 확인하고
> 안 지키면 해당 규칙을 압축본에서 더 명시적으로(트리거 단어 강하게) 다시 박아.
