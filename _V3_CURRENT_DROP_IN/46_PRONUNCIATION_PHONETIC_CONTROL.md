# 위상: 14(운율)·25(사운드)에 *Suno 오발음 방지 플레이북*을 더함 — 실패유형 진단 + 음소 리스펠링 + 범위 규율.
# 발동: 발음 깨짐("이 단어 이상하게 불러")·고유명사/숫자/약어 포함·다국어·로봇 후렴.
# ★핵심: Suno는 *의미가 아니라 철자로* 노래한다(사전 조회 불가, 패턴 예측) → 묵음·동철이음·약어·숫자·고유명사가 망가진다. 고침 = 소리나는 대로 리스펠링, **생성 *전에*** (생성 후 가사 발음은 못 고침).

## §0. 원리 — 철자로 노래한다
Suno는 훈련 데이터의 *철자 패턴*으로 발음을 예측한다. 불규칙 철자·묵음·중의 철자를 만나면 *틀리게 추측*. 사전을 못 본다.
→ 대책 = 맞춤법이 아니라 *소리나는 대로* 적기(SEER-sha for Saoirse). 단 §3 범위 규율(전부 리스펠링 X) + §4 비라틴 스크립트 예외.

## §1. ★실패 유형부터 진단 (도구·리스펠링 먼저 고르지 마)
발음 문제를 다 같게 취급하면 헛수고. *실패 유형 먼저* 판정:
```
증상                      진단 → 고침
──────────────────────────────────────────────────────
특정 단어가 계속 틀림       철자 문제 → §2 음소 리스펠링 또는 더 쉬운 동의어(§3)
줄이 뭉개짐/씹힘           과밀(음절 초과) → 줄 단축·분할(§5 BPM×음절)
후렴이 로봇 같음           후렴 가사가 반복하기엔 복잡 → 훅 짧게+여백(§5)
보컬 전체가 이상          음색/보이스 문제 → Reuse Prompt·재생성·보컬 셋업 재구축(30)
한 번씩만 이상            생성 아티팩트(가사 문제 아님) → 재생성(같은 프롬프트, §15)
다국어 경계서 깨짐         언어 혼용 → 섹션당 한 언어(§4/§12)
```
→ 시스템 룰: *실패 유형 먼저, 도구 나중*. (30 렌더 제어와 연동 — 생성 후면 Control layer.)

## §2. 음소 리스펠링 카테고리 (라틴 스크립트 — 영어·고유명사·숫자)
```
카테고리       문제                      고침(소리나는 대로)
──────────────────────────────────────────────────────
묵음           silent letters 오발음      "often"이 't' 발음되면 "off-en" / 의도대로 소리 적기
동철이음        같은 철자 다른 소리         read(reed/red)·lead(leed/led)·tear(teer/tair)·bow(boh/bow)·
(homographs)                            live(liv/lyv)·wind(wind/wynd)·wound·tears → *원하는 소리로* 리스펠
약어/이니셜     acronym 뭉갬               의도가 글자읽기면 "A-I" / 단어면 "ay-eye" 또는 풀어쓰기
숫자/날짜       "2026" 여러 읽기           단어로: "twenty twenty-six" / "1990s"→"nineteen-nineties"
고유명사        ★최대 파탄점               이름/브랜드/지명/조어/캐릭터명 → 소리나는 대로(예: 의도 발음 적기).
(proper noun)                            단 *가사에 캐릭터명 자체 금지*면(35 §0) 보컬 디스크립터로 우회
연음/문장부호   apostrophe·hyphen 영향     축약·하이픈이 프레이징 바꾸면 풀거나 조정
외래어         영어식 발음 오류            의도 발음으로 리스펠(단 비라틴 본문은 §4)
```
→ 리스펠은 *생성 전* 가사에 직접. (강세·CAPS·늘림은 25/§8 — 발음은 *철자*, 강조는 *대문자/늘림*.)

## §3. 범위 규율 — 과용 금지 (★전부 리스펠링하지 마)
- *두 가지 이상 읽기가 가능한 단어* 또는 *반복 실패하는 단어*만 고친다. 멀쩡한 단어 리스펠 = 오히려 부자연.
- 한 단어가 20번 실패해도 붙들지 마 — *더 쉬운 동의어*로 교체(곡에 안 중요하면). 미션 크리티컬할 때만 리스펠 고집.
- 리스펠은 마지막 수단 — 먼저 정상 철자로 시도, 계속 틀리면 그때 음소 lock.

## §4. ★비라틴 스크립트 — 한글·가나 (YUNY 핵심, 절대 규율)
- **한글·일본어(한자/히라가나)는 Suno가 *네이티브로* 읽는다 → 리스펠링·romanization·별도 발음 가이드 절대 금지.**
  네이티브 스크립트 *자체가* 발음 가이드다. 별도 가이드 줄 추가 = *중복 보컬 라인* 유발(기존 §13/romanization 금지와 정합).
- 한국어 가사 = Hangul 직접 / 일본어 = 한자·히라가나 혼용 그대로(발음 줄 분리 X, 26 연동).
- 음소 리스펠링은 *비라틴 본문엔 적용 안 함* — 영어 단어·고유명사·숫자가 그 곡에 섞일 때만(그 부분만).
- **섹션당 한 언어**(§12 다국어 격리) — 한 verse 안 혼용 시 발음 드리프트. 의도적 코드스위칭(문장/단어 단위)은 가능하나 *불안정* → 운영자 명시 시만.
- 스페인어/라틴: 대체로 음소적(읽는 대로) — 단 고유명사·영어 외래어는 주의(§2). 27 연동.

## §5. 로봇 후렴 차단 (발음 인접)
- 로봇 같은 후렴 = 후렴 가사가 *깨끗이 반복하기엔 복잡*. → 훅을 *짧게* + 여백.
- 구조: 한 줄 ×2 반복 + 짧은 의미 줄 1개 / 짧은 질문 + 짧은 답. (반복은 음악의 기능 — §8.)
- BPM×음절(§5) 준수 — 후렴 음절 과밀이 로봇화의 주범.

## §6. 생성 후 (Control layer — 30 연동)
- 이미 생성된 곡의 발음은 *챗으로 "가수 고쳐줘"* 안 됨 → Control layer 작업:
  Remaster(미세 명료도 향상) / Replace Section + Edit Lyrics(국소 수정) / Reuse Prompt(보컬·가사·스타일 바꿔 재생성).
- **Stop rule:** 한 단어 3회+ 실패면 전략 바꿔(리스펠 또는 동의어) — 크레딧 낭비 말 것.
- 진단 먼저(§1) → 유형 맞는 Control 도구. (30 Bone/Skin/Finish·Prompt vs Studio 연동.)

## §7. 출력 직전 발음 체크 (내부)
```
□ 고유명사/브랜드/지명/조어 있나 → 소리나는 대로 리스펠(캐릭터명은 디스크립터 우회)?
□ 숫자/날짜/약어 → 단어로 풀어 적었나? ("2026"→"twenty twenty-six")
□ 동철이음/묵음 단어 → 의도 소리로 리스펠(필요한 것만)?
□ ★한글/일본어 본문에 romanization·발음 가이드 줄 안 넣었나? (네이티브 리딩 — 절대)
□ 섹션당 한 언어? (혼용 시 드리프트 — 의도적 코드스위칭만 예외)
□ 후렴 반복 가능하게 짧고 여백? (복잡 = 로봇화)
□ 과용 안 했나? (멀쩡한 단어 리스펠 X — 실패/중의 단어만)
□ 강세는 CAPS/늘림, 발음은 철자 — 역할 안 섞었나(25/§8)?
```
하나라도 걸리면 보강 후 출력(표면 보고 X). ★발음 = 생성 전 철자로 잡는다 — 한글은 그대로, 영어·고유명사·숫자만 소리나는 대로.
