# KOREAN SYLLABLE GRID & INFILL ENGINE — 빈칸 그리드·기계 검산·국소 수리
근거 [연구]: LLM은 음절을 머리로 못 센다 — 지시·프롬프트만으로 정확 음절 생성은 한 자릿수~20%대, 대형 모델도 음절 오류율 ~80% 실측. 반면 **빈칸 충전(fill-in) 방식은 80% 정확** — 같은 모델인데 방법이 결과를 바꾼다. 결론: **세지 말고, 틀을 먼저 만들고, 부어라. 그리고 기계로 검산하라.**

## 1. 그리드 생성 (S3d — 가사보다 플랜이 먼저)
산출물 = 생성 플랜 표: 폼(섹션 순서) → 섹션별 행수(장르 prior 밴드: DATASET_PRIORS) → 행별 음절 칸(BPM 매트릭스 + 멜로디 보존 번안이면 음표 수 = 칸 수).
예 (156 BPM 댄스록, 후렴 8행):
```
[Chorus] ①○○○○○○ ②○○○○○○○ ③○○○○○ ④○○○○○○○ …(행=6/7/5/7 음절)
```
칸은 *상한 가이드*지 자물쇠가 아니다 — ±1 음절은 박 재배치로 흡수, ±2부터 충전 실패.

## 2. 충전 (S7 — 조각 행을 칸에 붓기)
- 독백에서 깎은 행(S4)을 칸에 맞춰 호흡 절단으로 다듬는다. 깎는 우선순위: 조사 > 수식어 > 어미 축약(것이→게) — **내용어와 생각은 깎지 않는다**(정보가 안 들어가면 행을 나눈다, 단어를 으깨지 않는다).
- 칸이 남으면 작은 말(그냥/뭐/좀)·호흡으로 채운다 — 의미 없는 수식어 충전 금지.

## 3. 기계 검산 (의무 — 자가 집계 금지)
충전 후 Python으로 행별 한글 음절 블록 수를 센다:
```python
for i, line in enumerate(lyric_lines, 1):
    syl = sum(1 for ch in line if '가' <= ch <= '힣')
    print(i, syl, line)
```
예산 대조 → 초과 행만 §2 우선순위로 재깎기 → 재검산. 검산 없는 "맞을 거야"는 출력 금지(글자수 실측 의무와 동일 법).

## 4. INFILL 국소 수리 (LYRIC-REPAIR 기본 수단)
전면 재작성은 멀쩡한 행까지 죽인다 — 반복 불만의 주범. 프로토콜:
1. **동결**: 문제없는 행 전부 고정(1글자 불변).
2. **마스크**: 죽은 행만 빈칸으로 — 그 행의 ①음절 예산 ②받기 좌표(앞 행에 대한 7수 중 무엇이어야 하는가) ③어미 팔레트 ④사고 이동 종류를 마스크에 표기.
3. **후보 3**: 마스크 조건으로 3안 생성(독백 출처 우선, 신규면 행동/지각 비트).
4. **판정**: 받기 생존(인접 교환 테스트)+검산 통과 1안 선택. 전부 미달 → 재생성 1회 → 그래도 미달이면 그 섹션을 상류(S4)로.
적용 예: "벌스 2의 3행만 어색해" → 3행만 마스크·교체, 나머지 출력 동일 — 사용자가 승인한 행은 절대 흔들리지 않는다.

## 5. 폼 정체성 매트릭스 (구조 일관성 [연구→전이])
같은 폼 = 닮아야(후렴↔후렴: 통제 변이만 — defense-shift 경로 A/B 외 변형 금지) / 다른 폼 = 달라야(벌스↔후렴: 밀도·어미·카메라가 다르면 폼이 선다). 검사: 벌스 한 단을 후렴 자리에 넣어 읽어서 위화감이 없으면 폼 뭉개짐 — 섹션 정체성 재설계.

## 6. fail 신호
플랜 없이 조각 직행 / 검산 없이 "음절 맞췄다" 주장 / ±2 초과 행 방치 / 1행 수리에 전곡 재작성 / 동결 행 무단 변경 / 후렴 2가 무허가 자유 변형 / 벌스가 후렴 밀도.
