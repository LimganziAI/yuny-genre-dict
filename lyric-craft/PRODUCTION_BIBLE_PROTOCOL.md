# PRODUCTION BIBLE PROTOCOL — 곡당 1장의 내부 설계문서 (유기성 엔진, v4.5)
**문제**: 가사·CREATE·COVER·EXCLUDE가 각자 따로 만들어지면 "아무 AI에게 돌려 짜집기한 느낌"이 난다. **해법**: 8필드보다 먼저 Bible 1장을 쓰고, 모든 필드는 거기서 *파생*한다. 필드끼리 모순되면 Bible 위반으로 즉시 검출된다.

## 양식 (≤25행, 내부 작성 — 운영자에겐 정수 3-5줄만 1회 확인)
1. **로그라인 1줄**: 누가, 어디서, 무엇과 싸우다, 어떻게 끝나는가.
2. **포맷 축**: 풀곡/콩트, 대략 길이대(분량 숫자 아님 — 구조 규모).
3. **Key·BPM·구조 아크**: 섹션 순서와 에너지 곡선 1줄.
4. **보컬 물리 + 장르 보정**: 팔레트 [VOICE] + 이 장르에서의 보정(재즈=피치 앵커 상향 등).
5. **6-샷 스토리보드**: 장면을 카메라 6컷으로 — **카메라 이동 ≥3회**(광각→손→사물→얼굴→…). 각 컷이 섹션 1-2개를 먹는다. 가사가 한 자리에 머물면 이 항목 위반.
6. **훅 문장 + 어미 설계**: 훅 1문장(화자의 화행으로) + 챈트 여부 선언(챈트면 앵커 위치·사이 변주 계획).
7. **모티프 오너 + 등장 지점**: 어느 악기가 시그니처를 소유하고 어디서 들어오는가.
8. **COVER 전략**: 모드(질감 정제/장르 변환) + substitution 축 + Audio Influence 의도.
9. **EXCLUDE 클래스**: 이 곡이 흘러갈 위험 방향 3개.
10. **이 곡의 클리셰 밴**: 이 컨셉이 부르는 상투구 3-5개 금지(예: 빙수 곡 → "마음이 녹다" 금지).

## 파생 규칙
- LYRIC의 장면·사물 = 5번에서만. CREATE의 모티프·아크 = 3·7번에서만. COVER = 8번에서만. EXCLUDE = 9번에서만.
- 검출: 필드에 Bible에 없는 결정이 나타나면 — Bible을 고치든 필드를 고치든 *한쪽으로 정렬*. 무단 이탈 = 짜집기의 시작.
