# KOREAN TRANSLATION / ADAPTATION ALIGNMENT ENGINE — 번안·한국어화 SOP
대원칙: **번안은 단어 번역이 아니라 노래의 재탄생이다.** 보존하는 건 의미 문자열이 아니라 — speech act / line budget / hook function / repetition architecture / section pressure. 원문 가사·훅 문장 복제 금지(번역 복제도 복제다). 직역 이미지는 버리고 한국어 화자의 상황으로 다시 쓴다.

## 8단계
1. **Source function sheet** — 원곡에서 추출(문장이 아니라 기능): 전체 speech act 곡선(섹션별 화자가 *하는 일*) · 훅의 기능(합리화/도발/항복…) + 훅의 소리 형태(음절수·랜딩 모음·반복 구조) · 섹션별 행 수와 압력 변화 · 반복 아키텍처(무엇이 몇 번, 변이는 어디서) · 화자-청자 관계.
2. **Speaker transfer** — 원곡 화자를 한국어 화자로 *이식*: 같은 상황의 한국 사람이라면 누구인가(나이/말투/어미 팔레트). 원곡 화자의 직역이 아니라 등가 인물 — 여기서 카드 06 화자 설계 전체 적용.
3. **Line budget map** — 섹션별 행 수·호흡 예산을 원곡 구조에 맞춰 잡되, 한국어 음절 경제로 재계산(영어 8음절 행 ≠ 한국어 8음절 — 정보량 기준). 멜로디 보존 번안이면 음표 수 = 음절 예산.
4. **Hook function map** — 원문 훅 문장을 옮기지 말고 **기능+소리 스펙**만: "8음절, 자기합리화 화행, 열린 모음 랜딩, 2회 반복 후 3회째 변이" → 이 스펙으로 한국어 훅을 채굴(S3b — 한국어 독백에서).
5. **Korean plain speech draft** — 이식된 화자의 독백부터(LIVING_SPEECH 엔진 전체 적용). 원문을 옆에 두지 않는다 — function sheet만 보고 쓴다(원문 응시 = 직역투의 근원).
6. **Lyric compression** — 호흡 절단·line budget 맞춤.
7. **Prosody pass** — PHONETIC 채점: 랜딩 모음이 원곡 훅의 개방감과 등가인가(영어 'oh' 랜딩 ≈ 한국어 ㅗ/ㅏ).
8. **No-cloning check** — 원문 대조: 문장 단위 의미 1:1 대응 행이 30%+면 번역이지 번안이 아님 — 회귀. 훅이 원문 훅의 직역이면 즉시 재채굴.

## 직역투 차단 (번안 특화 — 카드 06 7-blacklist에 추가로)
영어 대명사 구조 직역(you가 매 행 "너는"으로) → 한국어는 생략+어미가 관계를 멘다 / 영어 의문문 직역("Don't you know?"→"모르겠니?") → 한국어 반문 화행으로("몰랐을까 봐?") / be동사 서술 직역("I'm broken"→"나는 부서졌어") → 상태의 물증으로("리모컨이 그대로네").

## 데모 (가상의 원문 — 실곡 아님)
원문(가상): "I left the light on again / like you're still coming home" — function sheet: 화행=습관 고백+헛된 기대 인정 / 사물=불 / 2행 1생각 / 랜딩 'home'(ㅗ급 개방).
직역(fail): "불을 또 켜뒀어 / 네가 아직 집에 오는 것처럼" — 처럼 직유 직역+정보 평행.
번안(pass): 한국 화자 독백 "불 끄는 걸 자꾸 까먹네. 까먹는 거 맞나." → 가사 "또 불을 켜뒀네 / 까먹은 거라 치자" — 화행 보존(습관+자기기만), 사물 보존, 직유 폐기, 한국어 화행(~라 치자)으로 재탄생, 랜딩 ㅏ.
